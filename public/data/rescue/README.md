# Rescue data

Static layers for the Soccorso ed Emergenza module. Every file here is
regenerated by a `pipeline/` script - do not hand-edit. This note records
where each one comes from and how it would be rebuilt today.

| File | Provenance | Rebuild |
|---|---|---|
| `aed.geojson` | **generated + curated** | `make rescue` |
| `hems.geojson` | **generated + curated** | `make rescue` |
| `fire_hydrants.geojson` | **generated**, empty (none mapped yet) | `make rescue` |
| `emergency_assembly_points.geojson` | **generated**, empty (none mapped yet) | `make rescue` |
| `fire_perimeters.geojson` | **generated** (IRDAT FVG WFS) | `make fire` |
| `fire_danger.geojson` | **generated** (IRDAT FVG WFS, clipped to boundary) | `make fire` |
| `fire_ignition_points.geojson` | **generated** (IRDAT FVG WFS) | `make fire` |
| `hospital.geojson` | **generated** (Overpass `amenity=hospital`, nearest one) | `make hospital` |
| `hospital_roads.geojson` | **generated** (Overpass driving network) | `make hospital` |
| `rii.geojson` + `rii/` | **curated** (Protezione Civile field survey) + OSM lines | `make rii` (only on a new source package) |

## Emergency assets (`build_rescue_geojson.py`, `make rescue`)

Overpass query for AED, HEMS, fire hydrants and assembly points; if Overpass
is unreachable the committed file is kept as-is.

- `aed.geojson` - defibrillators (DAE): `emergency=defibrillator` +
  `amenity=defibrillator`.
- `hems.geojson` - helicopter landing / HEMS: `aeroway=helipad` +
  `emergency=helipad|landing_site`.
- `fire_hydrants.geojson`, `emergency_assembly_points.geojson` - OSM has none
  in this comune yet, so these stay empty `FeatureCollection`s and the map
  simply shows no points.

### Curated lists: `data/rescue/aed_comune.geojson`, `hems_comune.geojson`

The comune-provided lists of DAE / helipads, geocoded from addresses. They
live under `data/rescue/` (a curated input), not here. `merge_curated()`
writes `<layer>.geojson` = OSM features + any curated point with no OSM node
within ~60 m, so once a device is added to OSM it supersedes its geocoded
point with no duplicate. Today OSM already covers every curated DAE, so
`aed.geojson` is pure OSM; `hems.geojson` is the three curated helipads
(OSM maps no helipad here). `geocoded: true` / `geo_precision` mark points
placed from an address - the popup flags them "da verificare sul posto".

## Incendi boschivi (`build_fire_geojson.py`, `make fire`)

Regione FVG, IRDAT dataset 1232 ("Perimetro degli incendi boschivi" -
perimeters digitised from the Fogli Notizie Incendi Boschivi filed by the
Stazioni Forestali, with GPS field surveys), pulled from the regional
GeoServer WFS (`ZONE_RISC`) and filtered by comune.

- `fire_perimeters.geojson` - `V_INCENDI_CT`. Year, locality, start date,
  duration, ignition place, vegetation state, cause; `causa_classe`
  (dolosa/colposa/naturale/ignota) drives colour and filtering.
- `fire_danger.geojson` - `SITFOR_PERICOLO_INCENDI` regional danger zonation
  (`grado` medio/alta), clipped to `public/data/boundary.geojson`.
- `fire_ignition_points.geojson` - `V_INCENDI_PUNTOINIZIO`, filtered by the
  comune's forest stations and matched to its perimeters, plus any point
  inside the boundary.

Only FVG comuni get data - elsewhere the queries return empty
`FeatureCollection`s. It is a historical archive, not a predictive hazard
map; the SITFOR overlay is a coarse propensity zonation, not a live alert.
The tab also reuses `../nbr.geojson` (Green module) as an optional burn/
dryness backdrop.

## Ospedale piu' vicino (`build_hospital_geojson.py`, `make hospital`)

- `hospital.geojson` - one Point: the nearest `amenity=hospital` on OSM,
  found by a growing-radius Overpass search from the town centre, with its
  address rebuilt from the `addr:*` tags.
- `hospital_roads.geojson` - a driving road network (OSMnx-style edges keyed
  by OSM node id) covering the bounding box of the comune plus that
  hospital, padded ~1 km. The nearest hospital sits in a neighbouring
  comune and `public/data/transport.geojson` is clipped to this comune's
  boundary, so the in-browser router needs its own network to draw the whole
  route (see `lib/routing/graph.ts` -> `loadDrivingGraph`).

## Rii a rischio esondazione (`build_rii_geojson.py`, `make rii`)

A comune-specific volunteer field survey (Censimento RII) by the Gruppo
Comunale di Protezione Civile - one point per rio, with a representative
photo, the described criticality and proposed interventions. **Not** a
technical study and **not** a live feed. Rebuilt only when a new source
package is delivered.

Two inputs are merged:

- `data/sources/output_rii_protezione_civile.zip` - CSV attributes + photos
  (not committed; not part of the material provided so far - the committed
  `rii.geojson` was carried over from the old data disk).
- `pipeline/scripts/rii_osm_lines.geojson` - the real watercourse geometry
  from OpenStreetMap (ODbL), keyed by census id. Where OSM has the named
  stream the layer draws its line; otherwise a point flagged approximate.

Every rio has a `Point` marker; rii that OSM maps also carry a `LineString`
sharing the feature id. Marker/line colour encodes how current the survey is
(`stato`). Photos are web-resized into `rii/`. Rii with no usable location
are skipped (mentioned in the module FAQ). For a comune without this data,
leave `rii.geojson` as an empty `FeatureCollection`.
